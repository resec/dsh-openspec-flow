# Proposal: Complete OpenSpec toolset and skill adaptation

## Why

The plugin currently covers only the apply loop. An agent working in an OpenSpec project still has to run the CLI by hand for propose, new, status, instructions, show, validate and archive, which means shell quoting, output parsing and repeated full-payload reads. The six official skills generated by `openspec init --tools dsh` also instruct the agent to run the CLI, so the tools and the skills pull in different directions.

## What Changes

- Add eight tools: `openspec_instructions`, `openspec_show`, `openspec_context`, `openspec_schemas`, `openspec_store_list`, `openspec_new_change`, `openspec_archive` and `openspec_init`.
- Extend `openspec_list` with a `specs` mode and `openspec_validate` with a `scope` and `strict` option.
- Add `openspec_init`, which runs `init --tools none`, writes six plugin skills into the project, and migrates official skills after backing them up.
- Rewrite the six generated skills to call the tools first and fall back to the CLI only when the tools are unavailable.
- Map the CLI commands embedded in `instructions` output to the corresponding tool names.
- Extend the scoped policy from the apply gate to the whole workflow.
- Keep the bundled CLI as the authority for schema, root, store, validation and archive semantics.

## Capabilities

### New Capabilities

- `tool-surface`: the agent-facing tool set, its inputs, projections, error semantics, schema gate and store handling.
- `skill-adaptation`: plugin-generated skills, official-skill migration, version refresh, tool-first guidance and instructions text mapping.

### Modified Capabilities

None. The existing `development-workflow`, `flow-policy`, `cli-bundling` and `schema-compatibility` specs stay in force.

## Impact

- `lib/tools.js` is split into `lib/tools/query.js`, `lib/tools/apply.js`, `lib/tools/write.js` and `lib/tools/index.js`.
- New `lib/init.js` and `lib/skills.js`.
- `lib/policy.js`, `index.js`, `skills/openspec-*/SKILL.md`, `test/`, `README.md`, `AGENTS.md` and `locale/` change.
- `package.json` keeps `@fission-ai/openspec` 1.16.0 as the runtime dependency.
- Existing projects need one explicit `openspec_init` call to replace their official skills.
